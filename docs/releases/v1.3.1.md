# v1.3.1 — evaluation contract and resume locks

## Changes

- Synchronize the Agent evaluation contract with the main-platform develop API, including `locked`, `lockedReason`, `attackStatus`, `repairStatus`, `history`, `syncStatus`, and direction-score fields.
- Expose `alreadySolved` in the Flag-submission result schema.
- Document the resume policy: completed or `timed_out` runs remain read-only by default; Agents call `evaluation run start` on them only when the user explicitly requests a resume.
- Document resume-period locks. Only new questions and questions requiring retesting are available; locked questions must be skipped, and the lock conflict is non-retryable.
- Document the distinction between `locked: true` and `kind: "unavailable"`, plus the no-op behavior of `alreadySolved: true` after a passed attack question.
- Keep generated evaluation bindings produced by `make generate-evaluation`; management-only contract additions such as collections are not included in the Agent endpoint manifest.

## Upgrade

Replace the v1.3.0 executable with the matching v1.3.1 release asset after verifying `SHA256SUMS`. Run:

```sh
ctfpc9n-cli help evaluation run start
ctfpc9n-cli help evaluation challenge list
ctfpc9n-cli help evaluation submission flag
```

Update the bundled `skills/ctfpc9n-cli/SKILL.md` together with the executable. Agents must not resume a completed or timed-out run unless the user explicitly asks for it. Agents must skip locked and unavailable questions, avoid retrying the documented lock conflict, and stop submitting a question after `alreadySolved: true`.
