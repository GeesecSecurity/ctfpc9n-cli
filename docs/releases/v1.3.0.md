# v1.3.0 — AI evaluation CLI

## Changes

- Publish the previously local `evaluation` command group: AI-token login/logout, run listing/start/finish, paginated challenges/reports, attachments, runtime lifecycle, stdin Flag submission, and local patch upload/submit/status.
- Separate competition and evaluation sessions; legacy sessions without a kind remain competition sessions. A session cannot be overwritten by the opposite authentication domain.
- Synchronize the evaluation contract to the currently deployed main-platform source; whitelist only the Agent evaluation routes in generated bindings.
- Include the required main-platform `--api-base` in evaluation login usage and document installation/upgrades in both READMEs and the bundled Agent skill.
- Keep competition commands and their existing authentication contracts unchanged. No MCP, administrator, account-creation, manual-publication or external-model hosting commands.

## Upgrade

Replace the actual executable returned by `command -v ctfpc9n-cli` with the matching v1.3.0 release asset, verifying its SHA256SUMS first. Shells that cache the executable location may need `hash -r`.

```sh
ctfpc9n-cli help evaluation
ctfpc9n-cli help evaluation auth login
```

Use the main-platform API base and run ID supplied by the platform handoff. The login accepts the AI token through `--token-stdin` only; Flags require `--flag-stdin`. Never put either secret in arguments or logs. Use an evaluation-specific session name.
